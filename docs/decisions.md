# Decisions

Intentional choices visible in the code that can look unusual to a newcomer. These are deliberate, not defects. For problems, see [inconsistencies-tech-debt](inconsistencies-tech-debt.md). For narrative trade-off discussion, see [justifications](justifications.md).

| Decision | Why chosen | What NOT to do | Source |
|----------|------------|----------------|--------|
| Base image `debian:trixie` is left unpinned (no digest) | Rebuilds pick up Debian security updates automatically, without a manual digest bump | Don't pin `FROM debian:trixie` to a `@sha256:` digest. The residual risk is tracked in [TD-20261018-unpinned-base-images](tech-debt/TD-20261018-unpinned-base-images.md) | [src: file: Containerfile:3] |
| The standard image runs Debian's own kernel (`linux-image-amd64` / `linux-image-arm64`) with the full hardware support Debian ships; only the minimal image installs the project kernel, through the virtual name `linux-image-${KERNEL_VARIANT}-${ARCH}` (default `minimal`) | The project takes no kernel responsibility for the standard image, and Debian's kernel keeps every driver. The custom kernel is the deb `daemoncores-kernel-<kver>`: it Provides `linux-image-minimal-<arch>` and Conflicts with and Replaces the Debian `linux-image-<kver>` it overlaps, like the ostree package does with libostree | Don't install the project kernel or its `linux-modules-*` packages in the standard image, don't make the custom kernel Provide `linux-image-<arch>`, and don't install `linux-headers` (not published in the project APT repo) | [src: file: Containerfile:18] [src: file: Containerfile:85-87] [src: file: workflows/bootc-debs-builder/packages.yml:169-181] |
| `.github/workflows/pipeline.yml` is a thin caller of the shared `DaemonCores-CI` `full-pipeline.yml` | GitHub evaluates triggers and concurrency in the caller, not in the reusable workflow; the whole job graph lives in the shared reusable workflow | Don't add jobs or steps to `pipeline.yml`. Don't move triggers or concurrency into the shared workflow | [src: file: .github/workflows/pipeline.yml:3-15] |
| Per-deb content cache keyed only on declared `sources` paths and non-secret `env`; `secret-env` is never hashed | An unchanged package is restored from the published APT repo instead of rebuilt | Don't add a build input (file, version, env var) without declaring it under that package's `sources`/`env`, or the cache serves a stale `.deb`. Don't put secrets in `env` | [src: file: workflows/bootc-debs-builder/packages.yml:7-10] |
| Every runtime test must declare a `diag` command; the harness fails the build otherwise | A failing boot test must always capture the runtime state behind the failure | Don't add a test to `workflows/tests.yml` without `diag`. Don't drop the `arch`/`variant` gates on target-specific tests | [src: file: workflows/tests.yml:9-12] |
| APT signing key fetched with `wget` and checked against `BOOTC_GPG_SHA256`, a build argument the CI derives from the `APT_GPG_KEY` secret (the published key must carry the secret's fingerprint) | The build fails if the downloaded key bytes differ from the digest; no hash is committed, so rotation needs no commit | Don't replace this with `ADD <url>` or skip `sha256sum -c`. The Containerfile default only serves local builds | [src: file: Containerfile:35-38] [src: file: Containerfile:71-75] |
| `policy-rc.d` returns `101` during the build and is deleted in the final phase | The build container has no init; services must start only on the real first boot | Don't remove the hook early or start daemons in a `RUN`. Don't ship it in the final image | [src: file: src/debianpreinstall/usr/sbin/policy-rc.d:3-8] [src: file: Containerfile:181] |
| Kernel finalization (relocation into `/usr/lib/modules/<kver>/`, dracut initramfs) runs from a `postinst.d` hook shipped in the `bootc` deb | Any Debian-based downstream image that installs or updates a kernel gets the OSTree layout automatically | Don't require downstream Containerfiles to call `bootc-finalize` by hand, and don't move the hook out of the `bootc` package | [src: file: workflows/bootc-debs-builder/bootcpostinstall/etc/kernel/postinst.d/zz-bootc-finalize:3-9] |
| APT signing key rotated by a CI cron that writes the `APT_GPG_KEY` secret; nobody pushes packages by hand | The APT repo is a GitHub Pages site, so only GitHub can publish to it, and an immutable bootc OS has no reason to push a package after the image build | Don't print, export as an output or upload the private key; don't pin a hash by hand: the pipeline derives it | [src: user:pikatsuto:2026-10-18: KT-5 decision]; `DaemonCores-CI/.github/workflows/rotate-apt-key.yml` (reusable, called by `.github/workflows/rotate-apt-key.yml`) |
| GRUB is always built from the Fedora source (`rhboot/grub2`), never taken from Debian | bootc and bootupd need the GRUB modules and configuration of the Fedora build; Debian's GRUB has neither | Don't stage or install Debian's `grub-efi-*-signed`, not even as an arm64 fallback | [src: user:pikatsuto:2026-10-19: GRUB Fedora is mandatory] [src: file: workflows/bootc-debs-builder/packages.yml:741] |
| The Fedora GRUB follows the head of the `rhboot/grub2` default branch (rolling), resolved by `upstream-track` before each build; the package version is derived from the source (`1+<GRUB>+<commit date>+<branch>`) | Same rolling-release policy as the rest of the stack: no commit pinned in the repository, and a head that fails to build keeps the last-good deb | Don't reintroduce `GRUB_PINNED_COMMIT`, `GRUB_FEDORA_BRANCH` or a hard-coded `GRUB_VER` | [src: user:pikatsuto:2026-10-19: pin the Fedora mainline branch, not a commit] [src: file: workflows/bootc-debs-builder/packages.yml:752-757] |
| arm64 has two boot profiles chosen by `LABEL org.daemoncores.boot-profile`: `generic` (Fedora GRUB, UEFI machines and VMs) and `embedded` (U-Boot, boards and phones); amd64 is always generic | A UEFI arm64 machine needs GRUB like amd64, while Raspberry Pi class devices load U-Boot and have no use for GRUB | Don't derive the boot stack from the architecture alone, and don't ship Debian's GRUB for the generic profile | [src: file: Containerfile.minimal:93] |

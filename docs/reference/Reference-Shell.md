## `src/buildisopreinstall/sbin/policy-rc.d`

policy-rc.d - deny all daemon start/restart actions during the image build.
dpkg/apt invoke this hook before (re)starting a service on package install;
returning 101 tells the invoke-rc.d helper "forbidden", so no daemon runs
inside the build container (there is no init there and services must start
only on the real first boot).

## `workflows/bootc-debs-builder/bootcpostinstall/usr/local/bin/bootc-finalize`

bootc-finalize - finalize the bootc image's kernel and bootloader layout.
Moves the newest kernel into /usr/lib/modules/<kver>, regenerates the
initramfs with dracut, and stages the signed shim/GRUB EFI binaries where
bootupd expects them. Invoked from the bootc package postinst during build.

## `workflows/bootc-debs-builder/bootcpostinstall/etc/kernel/postinst.d/zz-bootc-finalize`

zz-bootc-finalize - autonomous bootc kernel finalizer.

Shipped by debian-bootc's bootc package so that ANY Debian-based downstream
image (Proxmox-Atomic or otherwise) that installs or updates a kernel gets
that kernel relocated into /usr/lib/modules/<kver>/vmlinuz with a fresh dracut
initramfs - the layout ostree requires to deploy. This is what lets the base
integration propagate on its own: the downstream Containerfile does not need
to call anything, the standard Debian kernel-install machinery
(run-parts /etc/kernel/postinst.d) fires this hook automatically.

run-parts invokes us with: $1 = kernel version, $2 = kernel image path. We let
bootc-finalize pick the newest installed kernel (the one just installed on an
upgrade), so the args are informational only.

Defensive by design: during the base image's own build this hook may fire
while the bootc toolchain is only partially unpacked. If the finalizer's tools
are not yet available we defer silently - the bootc package postinst re-runs
bootc-finalize as an end-of-transaction backstop, and bootc-finalize is
idempotent, so the final state is always correct.

## `workflows/bootc-debs-builder/firstbootpostinstall/usr/local/bin/firstboot-user-setup`

firstboot-user-setup
First-boot TUI for user account and root password setup.
Launched by firstboot-user-setup.service before getty@tty1.
Modeled after Raspberry Pi OS userconfig.service.

The interactive wizard creates the user account, sets the root
password, and configures sudo, the SSH root-login policy, the
hostname, and the locale/keyboard layout.

## `scripts/e2e-local.sh`

e2e-local.sh - run the CI boot test (workflows/tests.yml) against a local
image, using the same harness as CI (DaemonCores-CI/image-test/image-test.sh).

Usage: scripts/e2e-local.sh IMAGE [ARCH]
  IMAGE  image already present in local podman storage (e.g. localhost/x:minimal)
  ARCH   amd64 (default) or arm64

Environment:
  CI_REPO  path to a DaemonCores-CI checkout (default: ../DaemonCores-CI)

The harness installs QEMU with apt-get and needs sudo, so this runs on a
Debian/Ubuntu host with /dev/kvm. It is not usable inside the dev container.

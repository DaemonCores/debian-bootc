## `src/buildisopreinstall/sbin/policy-rc.d`

policy-rc.d - deny all daemon start/restart actions during the image build.
dpkg/apt invoke this hook before (re)starting a service on package install;
returning 101 tells the invoke-rc.d helper "forbidden", so no daemon runs
inside the build container (there is no init there and services must start
only on the real first boot).

## `src/buildisopreinstall/usr/libexec/debian-bootc/mok-stage`

Queue the DaemonCores Secure Boot certificate and every public certificate
dropped in MOK_DIR for MOK enrollment, in ONE request (one password).

Runs as root (through pkexec) from the live installer session once the
install succeeded. The one-time MokManager password is read from stdin so it
never appears in a process list or a log.

## `workflows/bootc-debs-builder/bootcpostinstall/usr/local/bin/bootc-finalize`

bootc-finalize - finalize the bootc image's kernel and bootloader layout.
Moves the newest kernel into /usr/lib/modules/<kver>, regenerates the
initramfs with dracut, and stages the signed shim/GRUB EFI binaries where
bootupd expects them. Invoked from the bootc package postinst during build.

## `workflows/bootc-debs-builder/bootcpostinstall/etc/kernel/postinst.d/zz-bootc-finalize`

zz-bootc-finalize - autonomous bootc kernel finalizer.

Shipped by debian-bootc's bootc package so that ANY Debian-based downstream
image (Proxmox-Atomic or otherwise) that installs or updates a kernel gets
that kernel relocated into /usr/lib/modules/<kver>/vmlinuz with a fresh dracut
initramfs - the layout ostree requires to deploy. This is what lets the base
integration propagate on its own: the downstream Containerfile does not need
to call anything, the standard Debian kernel-install machinery
(run-parts /etc/kernel/postinst.d) fires this hook automatically.

run-parts invokes us with: $1 = kernel version, $2 = kernel image path. We let
bootc-finalize pick the newest installed kernel (the one just installed on an
upgrade), so the args are informational only.

Defensive by design: during the base image's own build this hook may fire
while the bootc toolchain is only partially unpacked. If the finalizer's tools
are not yet available we defer silently - the bootc package postinst re-runs
bootc-finalize as an end-of-transaction backstop, and bootc-finalize is
idempotent, so the final state is always correct.

## `workflows/bootc-debs-builder/lib/kernel-prepare.sh`

Shared kernel-module build bootstrap, sourced by the build: blocks of
linux-modules-arm-device in packages.yml. Listed in its sources: so a change
invalidates the cached debs.

Inputs (set by the caller): DEB_ARCH, SAVE_PWD (repository root), and
optionally KERNEL_SUFFIX ("-16k" selects the 16 KB arm64 kernel, empty or unset
the default 4 KB one).
Outputs (globals): COMMON_DEB, BUILT_VER, KVER, SRCDIR, ARCH (kernel arch).
BUILT_VER and KVER are consumed by the sourcing build: blocks.
Leaves the shell inside the kernel source tree with .config seeded from the
published linux-image-common deb; the caller merges its overlays and builds.

## `workflows/bootc-debs-builder/lib/kernel-signing.sh`

Kernel module signing setup, sourced by the kernel and kernel module build:
blocks of packages.yml. Listed in their sources: so a change invalidates the
cached debs.

The kernel signs every module at modules_install time with
CONFIG_MODULE_SIG_KEY (certs/signing_key.pem by default) and trusts the
matching certificate through its built-in keyring. Giving the build the CI
key at that default path makes the kernel image and the device module
packages sign with ONE key, so every module verifies against the kernel.

When signing is active the kernel also ENFORCES it: unsigned or foreign
modules are refused, and the secondary and machine keyrings are built in so
a certificate enrolled through MOK (see mok-stage) is trusted for modules.
KERNEL_SIGNING_ENFORCE=no builds the unsigned-kernel variant: same key, same
keyrings, but MODULE_SIG_FORCE off, so a signed module still loads there.

CONFIG_MODULE_SIG is on in EVERY kernel, enforcing or not: it changes the
layout of struct module, so the modules (always signed, one package shared by
both kernel variants) only load on a kernel that has it. Without a key
nothing is signed and nothing is forced.

Inputs (environment): MODULE_SIGNING_ACTIVE ("yes" to sign), and when active
MODULE_SIGNING_KEY and MODULE_SIGNING_CERT (PEM secrets of the CI);
KERNEL_SIGNING_ENFORCE ("no" to leave MODULE_SIG_FORCE off, default "yes").

## `src/basepostinstall/usr/libexec/debian-bootc/ostree-layout`

Convert the image filesystem layout to what bootc/ostree requires.

/home, /root, /mnt, /srv and /opt must be symlinks into /var so the read-only
/usr tree can be swapped atomically while mutable state persists in /var.
Shared by Containerfile and Containerfile.minimal; do NOT change the layout
or bootc fails.

## `src/basepostinstall/usr/libexec/debian-bootc/install-signature-policy`

Make the host require this repository's image signature.

Usage: install-signature-policy IMAGE_REF PUBLIC_KEY_BASE64

Writes the repository's cosign public key and a containers-image policy that
only accepts signed images for IMAGE_REF, plus the registries.d entry that
lets the host fetch the signature attached to the image. Every other
transport and registry keeps the default (accept anything) behaviour, so the
host can still pull its other images.

Does nothing when the public key is empty: a repository that has not
generated its signing key yet (first CI run, or no PAT_SECRETS) ships images
without a policy rather than a policy no image can satisfy. Shared by
Containerfile and Containerfile.minimal.

## `src/basepostinstall/usr/bin/autoupdate`

Switch the automatic bootc updates on or off.

Usage: autoupdate enable|disable|status

Automatic updates are driven by bootc-fetch-apply-updates.timer, enabled by
the bootc package. Masking it (a symlink to /dev/null in /etc/systemd/system)
is the opt-out the bootc-installer writes at install time; this command does
the same on devices that were not installed with the bootc-installer, such
as embedded boards flashed from a disk image. Shared by Containerfile and
Containerfile.minimal.
